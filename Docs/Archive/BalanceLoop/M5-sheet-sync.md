## 만든 것

### 1. 시트 쪽 웹 앱 `Docs/BalanceLoop/sheet-sync/BlackholeSheetSync.gs`

- 시트에 붙은 Apps Script 파일 하나다. 이름은 모두 `bh`로 시작하고, `doGet`·`doPost`만 정해진 이름이다.
- 모든 요청은 POST(JSON)이고, 본문의 `token`이 스크립트 속성 `BH_SYNC_TOKEN`과 같아야 한다.

| action | 하는 일 |
| --- | --- |
| `ping` | 시트 이름과 탭 4개가 있는지 |
| `read` | 탭을 시트 메뉴 "파일 > 다운로드 > CSV"와 같은 모양으로 준다: 보이는 값, 쉼표·따옴표·줄바꿈이 든 칸만 따옴표, 줄 끝 CRLF, 마지막 줄바꿈 없음, 끝의 빈 행 없음. 레포 CSV가 이 모양이라 같은 시트면 바이트까지 같다 |
| `write` | `{tab, keys, column, value, expected}` 목록. 키로 행을 찾고, 지금 값이 `expected`일 때만 쓴다. 하나라도 틀리면 아무것도 쓰지 않는다. 이미 새 값이면 쓰지 않고 `already`. 문서 잠금으로 동시 쓰기를 막는다 |

- 표시 칸("+25%")은 수식이 아니고 이전 값의 표시와 같을 때만 새 값으로 맞춘다. 숫자로 바뀌지 않게 글자로 쓴다.
- `bhSyncSetupToken`은 토큰을 만들어 저장하고 로그에 보인다. `bhSyncShowToken`은 지금 토큰을 보인다.

### 2. 에디터 BlackHole > Sheet Sync (`Editor/Playtest/SheetSyncWindow.cs`, `Editor/Playtest/SheetSync.cs`)

- 설정: 웹 앱 주소·토큰. 저장하면 `PlaytestData/sheet.json`(git 무시)에 들어간다. "연결 확인"은 시트 이름과 탭 수를 보인다.
- 시트에서 끌어오기:
  1. 탭 4개를 읽고 레포 파일의 줄 끝에 맞춘다.
  2. 행 단위로 비교한다(`SheetDiff`). 키는 UpgradeStats는 StatId, Nodes는 NodeId, NodeCost는 NodeId·Rank, NodeEffects는 NodeId·Rank·StatId다. 바뀐 칸, 새 행, 없어진 행, 새 칸, 없어진 칸을 보인다. 값이 같고 글자 모양만 다르면 따로 알린다.
  3. 게임과 같은 길로 검사한다(`NodeSheetCheck`): CSV 읽기, 노드 콘텐츠, 노드 트리(배치에 있는 노드가 시트에서 없어지면 오류), 노드 × 콘텐츠. 오류가 있으면 덮지 않는다. 배치하지 않은 새 노드는 경고만 한다.
  4. 시트에 아직 안 옮긴 레포 변경을 확인한다. 그 칸이 시트에서 아직 이전 값이거나 따로 바뀌었으면 "덮으면 사라진다"고 알린다.
  5. 덮어쓰기: 바뀐 탭의 CSV를 시트 글로 덮는다. 수치 감시(M2)가 바로 반영하고, 변경 기록에 `pull`을 남긴다(노드 값 칸은 경로별 이전·이후, 나머지는 summary).
- 시트에 반영: 아직 안 옮긴 promote·revert 기록의 노드 값을 칸마다 합친다(처음 이전 값 → 마지막 이후 값, 바꿨다 되돌린 칸은 빠진다). 웹 앱에 쓰고 `sheet` 기록을 남긴다.
  - 버튼은 늘 보인다. 옮길 변경이 없거나 웹 앱 주소·토큰이 없으면 회색이고, 아래에 이유를 적는다(사용자 요청, 10-10).
- 자동 끌어오기(기본 꺼짐):
  - 켜면 간격마다(기본 30초, 최소 10초) Unity가 앞에 있을 때만 시트를 읽는다.
  - 바뀐 것이 있고 덮어도 잃을 것이 없으면 덮는다. 잃을 것이 있으면 보류하고 이유를 창과 콘솔에 한 번 알린다.

### 3. 기록과 계산 (`Playtest/ChangeRecord.cs`, `Playtest/SheetSyncPlan.cs`, `Playtest/SheetDiff.cs`)

- 변경 기록 종류: `promote`·`revert`(M4) + `pull`(시트에서 끌어옴, author `sheet`, appliedBy `human`·`auto`) + `sheet`(시트에 씀).
- `syncOf`: 이 기록으로 시트와 맞춰진 앞 기록. `summary`: 사람이 읽는 요약.
- 미반영: 노드 경로가 있는 promote·revert 가운데 `syncOf`에 든 적 없는 것. 끌어와 덮으면 레포 = 시트이므로 그때의 미반영도 모두 `syncOf`에 넣는다.
- AI 묶음의 `changes`에 pull 기록이 보이므로, 기획자가 시트에서 바꾼 값도 AI가 읽는다.
- Test Setup 창 "AI 조정"의 변경 목록에 끌어옴·시트에 반영이 보이고, 미반영이 있으면 "Sheet Sync 열기"가 나온다.

### 4. 네트워크 (`Playtest/SheetClient.cs`)

- HttpClient로 POST(JSON)한다. Apps Script는 응답을 다른 주소로 넘기므로(302) 넘김을 직접 따라간다: 302·303은 GET으로, 307·308은 같은 방법으로 다시 보낸다.
- 시간 초과는 30초다.
- JSON이 아닌 응답(로그인 페이지 등)은 "액세스 '모든 사용자'로 배포했는지, 주소가 /exec로 끝나는지"를 안내한다.
- 에디터 전용이다(`#if UNITY_EDITOR`). 개발 빌드에는 네트워크·토큰 코드가 들어가지 않는다.

## 설치 (사람이 한 번)

1. 구글 드라이브에서 `BlackHole_Node_Data` 구글 시트를 열고 **확장 프로그램 > Apps Script**로 간다. 편집 권한이 있어야 한다.
2. 왼쪽 "파일" 옆 **+ > 스크립트**로 새 파일을 만들고 이름을 `BlackholeSheetSync`로 한다.
   - 레포 `Docs/BalanceLoop/sheet-sync/BlackholeSheetSync.gs` 내용을 전부 붙여 넣고 저장한다.
   - 이미 있는 스크립트에 `doGet`이나 `doPost`가 있으면 이름이 겹친다. 그때는 알려 준다.
3. 위쪽 함수 목록에서 `bhSyncSetupToken`을 고르고 **실행**한다.
   - 권한 요청이 뜨면 승인한다(이 시트 읽기·쓰기).
   - 아래 실행 로그에 나온 토큰을 복사한다.
4. **배포 > 새 배포**를 누른다.
   - 유형 "웹 앱", 실행 사용자 "나", 액세스 "모든 사용자"로 고른다.
   - 배포한 뒤 웹 앱 URL(`…/exec`)을 복사한다.
   - 주소를 아는 사람도 토큰 없이는 아무것도 못 한다. 토큰은 각자 PC의 `PlaytestData/sheet.json`에만 둔다.
   - 스크립트를 고치면 **배포 관리 > 수정 > 새 버전**으로 다시 배포해야 반영된다.
5. Unity에서 **BlackHole > Sheet Sync**를 연다. 주소와 토큰을 넣고 "저장", "연결 확인"을 누른다. "연결됨: 시트 '…' · 탭 4/4"가 나와야 한다.

`PlaytestData/sheet.json` 모양:

```json
{
  "endpoint": "https://script.google.com/macros/s/…/exec",
  "token": "…",
  "csv": {},
  "tabs": {},
  "autoPull": false,
  "autoPullSeconds": 30
}
```

- `tabs`: 시트 탭 이름이 레포 CSV 이름과 다를 때만 적는다(예: `{"NodeCost": "비용"}`).
- `csv`: 웹 앱 없이 읽기만 할 때 탭별 CSV 주소를 적는다.

## 버전 관리

시트 자체에는 git 같은 버전 관리가 없다. 대신 세 겹으로 남는다.

| 겹 | 남는 것 | 되돌리는 법 |
| --- | --- | --- |
| 구글 시트 버전 기록 | 누가·언제 어느 칸을 고쳤는지(자동) | 파일 > 버전 기록 > 버전 기록 보기. 중요한 때는 "현재 버전 이름 지정" |
| 레포 CSV(git) | 게임이 실제로 쓴 값. 끌어올 때마다 줄 단위 diff가 생긴다 | git 커밋·되돌리기 |
| 변경 기록 `PlaytestData/changes.ndjson` | 반영·되돌리기·끌어옴·시트에 반영마다 이전·이후 값, 이유, 메모 ID, 지문 | Test Setup 창 "되돌리기" |

- 끌어온 뒤에는 CSV를 커밋한다. 그러면 시트의 그 시점 값이 git에 버전으로 남는다(예: `data: 시트에서 끌어옴 c-…`).
- 엑셀로 내려받은 xlsx는 그 순간의 사본일 뿐이라 고치지 않는다.

  - 쓴 뒤 다시 읽으면 그 칸과 표시만 바뀐다. 같은 쓰기는 already다.
  - 되돌려 쓰면 레포와 다시 같아진다. 기대값이 다르면 아무것도 쓰지 않는다.
  - 실행: `dotnet PlaytestTest.dll sheet-e2e <주소> <토큰>`. 실제 웹 앱에도 그대로 돌릴 수 있다. 시트를 바꿨다 되돌리니 테스트용 사본에 쓴다.

1. 위 "설치"를 하고 "연결 확인"에서 탭 4/4를 본다.
2. "시트에서 끌어오기"를 누른다.
   - 시트와 레포가 같으면 "레포 CSV가 시트와 같다"가 나온다.
   - 다르면 차이가 나온다. 레포가 시트보다 오래됐을 수 있으니 내용을 보고 덮는다.
3. 시트에서 비용 한 칸(예: `timer-01` Rank 1의 Cost 2 → 3)을 고친 뒤 다시 끌어온다.
   - 그 행만 차이에 나오는지 본다.
   - 덮어쓰면 `git diff`에 `NodeCost.csv` 그 줄만 바뀌는지, Test Setup 창 제목의 지문이 바뀌는지 본다.
   - `changes.ndjson`에 `pull` 기록이 생기는지 본다.
4. M4 초안을 반영(승격)했다면 Sheet Sync 창 아래에 미반영 칸이 보인다. "시트에 반영"을 누른다.
   - 시트의 그 칸(`Value`, `표시`)이 바뀌는지 본다.
   - 미반영이 0이 되는지 본다.
5. "자동 끌어오기"를 켠다. 시트에서 한 칸을 고치고 Unity로 돌아온다.
   - 30초 안에 콘솔에 `[시트] 끌어옴(auto)`이 뜨고, 플레이 중이면 같은 세팅·같은 시드로 다시 시작하는지 본다.
6. 3번에서 고친 칸을 시트에서 되돌리고 다시 끌어온다(또는 `git checkout`).

## 실제 시트에서 나온 문제와 고침 (10-10)

- 첫 끌어오기에서 CSV 끝에 `,,,,,` 같은 빈 행이 수백 개 붙었다(UpgradeStats 239, Nodes 352, NodeEffects 1181).
  - 원인: `BlackHole_Node_Data`는 Nodes의 Rank 수, NodeEffects의 단위·표시, UpgradeStats의 분석 칸에 수식이 아래로 300~1500행까지 미리 깔려 있다. 웹 앱이 그 행을 모두 읽었다. 시트의 CSV 다운로드는 끝의 빈 행을 넣지 않는다.
  - 게임은 빈 행을 건너뛰어 값은 같았다(검사 통과, 지문 9a787fff 그대로). 글자 모양만 달라 "값은 같고 글자 모양만 다르다"로 보였고, 그대로 덮어썼다.
  - 고침: 클라이언트가 읽은 탭의 끝 빈 행을 뺀다(`SheetDiff.TrimEmptyRows`). 이미 배포한 웹 앱을 다시 배포하지 않아도 된다. 스크립트도 같이 고쳤다(다시 배포는 선택).
  - 사용자 PC의 CSV는 끝의 빈 행을 빼서 되돌렸다. Nodes·NodeEffects는 커밋과 같아졌다.
- 남은 차이: UpgradeStats의 분석 칸 '구현 상태'가 시트에서는 60개 모두 `[2]동일한것`이다. 숨긴 원본_구분 탭이 가져오는 SystemCompare 시트의 '구분 입력' 값이다. 레포(10-04)는 네 종류였다. 게임은 이 칸을 읽지 않는다.
- git 줄 끝: 레포의 CSV는 저장소 안에서는 LF이고, 사용자 Windows 작업 폴더에서는 CRLF다(autocrlf). 연결된 VM에서 CSV를 커밋할 때는 `git -c core.autocrlf=true`로 해야 줄 끝 때문에 모든 줄이 바뀐 것처럼 커밋되지 않는다.

## 알려진 한계

- Apps Script에는 계정 종류마다 사용량 한도가 있다(동시 실행 수 등). 자동 끌어오기는 Unity가 앞에 있을 때만, 기본 30초 간격으로 한 번(탭 4개를 한 요청으로) 읽는다. 한도 오류가 나면 간격을 늘린다.
- 끌어오기는 바뀐 탭의 CSV를 통째로 시트 글로 덮는다. 분석용 칸(원작 이름·검사 등)도 시트를 따른다.
- 시트에 쓰는 칸은 NodeCost.Cost, NodeEffects.Value(+표시)뿐이다. 수치 정의(UpgradeStats)·노드 목록·Rank 수는 시트에서 사람이 고친다.
- 새 노드는 노드 도구에서 배치해야 트리에 들어간다(끌어오기는 경고만 한다).
- 회사·학교 구글 계정은 관리자가 "모든 사용자" 액세스를 막을 수 있다. 그러면 응답이 로그인 페이지가 되고, 창이 그렇게 알린다.
- 전투 기본값(에셋)은 시트에 없다. 그 변경은 레포 커밋으로만 공유된다.
