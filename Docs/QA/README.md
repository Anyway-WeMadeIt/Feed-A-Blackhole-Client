# 플레이 시점 재현

BlackHole → Test Setup에서 분류를 고르고 세팅을 불러온 뒤 ▶ 이 세팅으로 플레이한다.
AI, Claude, Google 계정, 서버 없이 동작한다. F1은 판 조작·HUD·로컬 메모다.
플레이해 보고 마음에 안 드는 점(느낌)과 고칠 방향은 BlackHole → Playtest Notes(플레이 메모 창)에 적는다. 플레이 중이면 지금 판, 아니면 Test Setup에 열린 세팅이 메모 대상이다.

## 구분
- 콘텐츠: 노드 가격·효과, 적·성장 에셋. 게임 규칙의 입력.
- 진행 상태: 보유 노드 Rank·남은 Gold·이정표 단계.
- 생성 조건: autoBuyBudget으로 현재 가격 기준 구매 가능한 가장 싼 Rank부터 구매. 동가면 NodeId ordinal 순.
- 판 시작 조건: 시작 Level·시드·시간 고정.
- QA 설명: category(분류), note(목적), expected(확인할 결과), contentFingerprint(저장 당시 수치).

자동 구매 예산은 추가 구매에 쓸 돈이다. 남은 예산은 버리고 시나리오 gold를 최종 보유 Gold로 쓴다.
JSON의 autoBuyBudget > 0은 현재 가격으로 매번 생성하는 레시피다.
창에 불러오면 확정 노드 목록으로 풀고, 저장할 때 autoBuyBudget=0인 스냅샷을 남긴다.
예산별 실험은 원래 레시피를 남기고 '다른 이름으로' 결과를 저장한다.

## 재현 조건
새 세팅의 시드는 1이다. 0이면 무작위이며 저장 전에 알린다. 게임에서 가져오기는 현재 판 시드도 가져온다.
저장 당시 수치 지문이 다르면 경고한다. 같은 세팅이어도 게임 코드·콘텐츠·입력 조작이 바뀌면 결과는 달라질 수 있다.
현재 진행을 가져오기는 판 전체 상태 저장이 아니다. 적 위치·남은 HP·누적 난수 상태를 복원하지 않고 같은 진행 조건으로 새 판을 만든다.
없는 노드·중복 ID·초과 Rank는 자동 보정하지 않고 거절한다. 트리상 구매 불가능 조합은 경고하며 개별 기능 테스트에 허용한다.
시작 Level 상승은 실제 EXP/성장 공급 경로를 쓰므로 자연 플레이 중간의 적 구성과 완전히 같지는 않다.

## 대표 세팅
- qa-first: 첫 판, 노드 없음, 고정 시드.
- qa-nodes-1~8: 노드 1~N단계를 모두 산 상태([노드 단계 세팅](NodeSuite/README.md)).

원하는 노드 계열은 '노드 계열 (ID 기준)'에서 찾는다. 화면 배치 구역이나 구매 경로를 의미하지 않는다.
노드 전체·정확 Rank·예산 구매와 단계/Level을 조합한 후 확인할 결과를 적어 공유한다.
세팅 JSON과 관련 .meta를 커밋한다. PC별 메모(PlaytestData)는 자동 공유되지 않는다.
수치 변경은 로컬 CSV/에셋 또는 수동 프로필로 시험한다. 시트 CSV는 수동 반입한다.

## Unity 확인
1. QA/기본 분류로 qa-first를 골라 플레이하고 F1/HUD를 확인한다.
2. 예산 구매 후 다른 이름으로 저장하고 JSON에 정확한 노드 목록과 autoBuyBudget=0이 있는지 본다.
3. 같은 파일을 다시 열어 노드·Gold·단계·Level·시드가 같은지 확인한다.
4. 세팅의 시작 Level을 이정표 직전(예: 9)으로 바꿔 '다른 이름으로 저장'한 뒤 실행해 전환·전장·적 구성을 확인한다.
5. CSV 값을 바꾸면 수치 감시와 지문 경고가 동작하는지 확인한다.
6. Sheet Sync·AI 조정 메뉴가 없고 외부 프로그램을 실행하지 않는지 확인한다.

## 자동 검증
`dotnet run --project Tests/QA/QA.csproj` (.NET 8). 게임 Core 전체와 세팅 실행 코드를 직접 컴파일한다.
동가 노드 구매 순서·Gold 처리·스냅샷·잘못된 ID/Rank·샘플 JSON을 검사한다.
JsonUtility는 테스트용 shim이므로 Unity 직렬화·에디터 UI 검증을 대신하지 않는다.
